[CRITICAL] Client reconnect не восстанавливает session при ошибке smux.Client
Файл: internal/client/client.go, функция handleReconnect

Описание:
При срабатывании handleReconnect (callback переподключения link) клиент закрывает старые session и conn, создаёт новый conn, но если smux.Client(c.conn, smuxConfig()) возвращает ошибку — функция возвращается с session=nil. При этом conn уже новый. Клиент остаётся в сломанном состоянии до следующего разрыва link.

func (c *Client) handleReconnect() {
    c.sessMu.Lock()
    if c.session != nil { _ = c.session.Close(); c.session = nil }
    if c.conn != nil { _ = c.conn.Close(); c.conn = nil }
    c.sessMu.Unlock()
    c.conn = muxconn.New(c.ln, c.cipher)
    sess, err := smux.Client(c.conn, smuxConfig())
    if err != nil {
        logger.Warnf("smux re-init failed: %v", err)
        return  // session остаётся nil, conn уже новый
    }
    c.sessMu.Lock()
    c.session = sess
    c.sessMu.Unlock()
}

Влияние: После любого переподключения link, если smux.Client не смог подключиться (даже transient error), клиент перестаёт обслуживать SOCKS5-запросы. Все запросы получают Host unreachable, пока link снова не разорвётся и не переподключится.

Рекомендация: При ошибке smux.Client — повторить попытку с backoff, или вернуть ошибку, чтобы link тоже знал о проблеме.
