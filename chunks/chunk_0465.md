☀️ Дневной дайджест OLC
сообщения 191836-192540, время 2026-07-15 08:59 - 2026-07-16 08:28 UTC

Дополнительно учтены ветки: DNS/WhiteDNS/StormDNS/MasterDnsVPN, Девлог, Вопросы, Баги, Сервисы для обхода БС.

🔥 Главное

Единого итога по работоспособности обходов за этот день не появилось: участники сообщали о сильно разном поведении VLESS, Naive и Hysteria в зависимости от сети и клиента. У некоторых связки на домашнем интернете работали, но с мобильного соединение не поднималось; в одном случае перенос конфигурации из Happ в Exclav дал результат.

Практический вывод из обсуждения: перед сменой протокола стоит проверить отдельно сеть, клиент, DNS и конфиг сервера. Один и тот же транспорт в чате одновременно называли рабочим и нерабочим, поэтому универсального «списка живых протоколов» здесь нет.

⠀
🧩 Naive, Hysteria, Mieru и клиенты

При установке через PXY участник получил рабочий VLESS, но Naive выдавал TLS handshake error, а HY2 не подключался. В ответах прозвучало, что Naive в Throne может запускаться нестабильно и иногда не проходит встроенную проверку, хотя соединение позднее появляется.

Ещё один замер: VLESS и HY2 давали около 300 Mbps на вход, тогда как Naive - порядка 10 Mbps. В обсуждении это назвали возможной нормой для конкретной связки, но полноценной диагностики причин не сделали.

По Mieru несколько участников сообщили, что он плохо переносит нестабильный интернет. Упоминалась схема Mita + Cloudflare WARP, но без подтверждения, что она решает проблему для всех.

⠀
🛠 olcrtc, WB, Jitsi и WDTT

В тестах Jitsi из белого списка комнаты падали при попытке подключить второго пользователя, включая ручной вход через браузер. В ответ на это один участник сообщил о форке olcrtc с созданием комнат через token.

В ветке «Вопросы» спросили, можно ли закрепить пользователя-модератора в WB VP8: после рестарта инстанса роль слетает. Готового решения в диапазоне не дали; в качестве альтернативы прозвучал WDTT с оговоркой, что проект ещё сырой.

⠀
🌐 CDN, российские сервисы и внешние IP

По CDN снова были противоречивые отчёты. На МТС один участник видел доступность CDN, другой - падение Yandex CDN. Для CDNvideo, Selectel, Baget и Timeweb обсуждали ручное закрепление IP, но это частное решение, которое требует постоянной проверки доступности адресов.

Отдельно обсуждали T-Банк: по сообщениям участников, он у части людей не открывался через зарубежный IP или через YC/VK CDN, хотя без VPN по Wi-Fi работал. Другие российские сервисы при этом могли оставаться доступными. Это не подтверждённое общее правило, а наблюдения из конкретных сетей.

Один участник заметил входящий запрос с кипрского IP почти сразу после добавления CDN-конфига. Причина не установлена, но это повод не оставлять панели и API открытыми наружу без необходимости.

GitVerse упомянули как зеркало GitHub с автоматической синхронизацией, однако частота, по обсуждению, может быть около раза в сутки. Для срочных изменений такой вариант создаёт заметную задержку.

⠀
🧩 StormDNS, DNS и российские площадки

В DNS-ветке продолжили обсуждать, как спрятать StormDNS за российским узлом. Один из вариантов: включить SOCKS5 на сервере StormDNS и дальше маршрутизировать трафик через 3x-ui на зарубежный VPS. Также обсуждали идею перенаправлять TCP/UDP 53 с российского VPS на удалённый сервер через NS-запись. Подтверждения готовой реализации в диапазоне не было.

Отдельно напомнили, что российский IP нужен не только для доступа к отдельным сервисам: встречаются геоблоки контента, например спортивных трансляций. Простая замена на зарубежный IP подходит не для каждого сценария.

⠀
🖥 Linux и инфраструктура

В стороне от обходов прошёл содержательный разговор о NixOS и принципе erase your darlings: корневая файловая система в RAM, а состояние собирается детерминированно после перезагрузки. Для этого упоминались impermanence и preservation.

Из дополнительных советов участника: попробовать dbus-broker вместо dbus, оптимизационные патчи и Lix вместо Nix. Это личные рекомендации из обсуждения, не проверенный набор настроек для всех систем.

✅ Что забрать с собой

Для Naive и HY2 важнее проверить конкретную сеть и клиента, чем сразу менять сервер: в диапазоне домашняя и мобильная сети давали разные результаты.

Для olcrtc/WB остаются открытыми вопросы с ролями модератора, созданием комнат и несколькими пользователями. Новые token-механизмы и форки стоит сначала тестировать отдельно.

CDN и российские IP нужно проверять на своём операторе и конкретном сервисе: работоспособность Yandex/VK CDN и банковских сайтов заметно различается.

Не публикуй API панелей и Xray наружу без необходимости. Даже неподтверждённые сообщения о незакрытом API - хороший повод перепроверить свои настройки.
