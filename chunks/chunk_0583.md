🔥 Главное

По обсуждению видно, что основной фокус дня — очередные блокировки CDN (Яндекс, затем VK), конфликт с Durev VPN и выход разоблачающей статьи, а также
находка API Телемоста 3.0 и ротация комнат/токенов через служебные API Яндекса.

Участники сообщали, что Яндекc-CDN отлетает при разном раскладе: у одного проработал около месяца и пропустил 320 ГБ даже с заглушкой-медиасервисом
(Lampac), у другого — 10 дней и 15 ГБ. Звучала версия, что триггерит не эндпоинт и не заглушка, а сам паттерн трафика: XHTTP долбится в один и тот же
путь. Обсуждали рандомизацию пути и ждали жёстких фиксов от разработчиков Xray.

Автор одной из украденных статей провёл переговоры с представителем Durev VPN: от «покажи патент» и «информация из открытых источников» до обвинений в
шантаже при упоминании DMCA. Затем вышла статья о Durev VPN — сайт/канал/чат. По сообщениям участников, сервис при этом рабочий: ~20 Мбит/с, 720p, ~300
руб/мес, но в условиях есть пункт о передаче данных по требованию РФ.

Нашли API Телемоста 3.0 и служебные API Яндекса: управление комнатами (создание, удаление, список участников) на стороне сервера без браузера и кук, с
токеном Яндекса. Работает ротатор комнат и токенов: токен живёт около месяца, обновляется через логин, до 2 комнат на профиль, есть задумка бесшовного
перехода между комнатами в olcbox.

🧩 DNS, белые списки и резолверы

Ветка «Днс проксирование» новых сообщений не имела, но в основном чате разобрали официальные белые списки операторов. Участник нашёл страницу МегаФона
(у каждого региона свой поддомен, например moscow.megafon.ru/offline_services) и подтвердил, что аналогичные страницы есть у МТС, Билайна, Т2,
Ростелекома/Yota, МОТИВ и СберМобайла — список формирует Минцифры, операторы лишь настраивают доступ.

Предложил прогнать эти списки сканом и собрать geosite-категорию для Хреца/антизапрета: российские сервисы пускать напрямую «ру на ру сервер», чтобы не
светить тунель. По обсуждению, это скорее материалы для энтузиастов, готовой базы пока нет.

Звучала версия про классификаторы на Соннете: владельцам серверов с IP, первая часть которых совпадает с подсетями госсервисов, прилетают письма с
требованием сменить адрес. Такие сервера будто бы работают в белых списках и без CDN.

🛰 CDN, xHTTP, Happ и БС

Практические выводы по CDN из диапазона:
- без каскада, по словам участника, CDN живёт дольше — у него трафик небольшой и его ещё не снесли;
- трафик передавать в заголовках, а не в URL; вариант с OPTIONS менее стабилен;
- заглушка обязательна: у одного заглушки не было — списали отлёт на это; кент с дефолтной страничкой nginx и без маршрутизации прогнал больше 2 ТБ,
прежде чем его откинули (10 дней, 14 ГБ — на дефолте);
- пути из гайда (api/stream) уже палево, советуют менять и «проявлять фантазию», а лучше поднять настоящий медиасервер;
- VK-CDN блокирует xhttp;
- свежий гайд: github.com/ServerTechnologies/proxy-via-russian-cdn.

Про протоколы: по сообщениям участников, vless «мёртв уже месяца три», нормально работает только hy2, reality живёт в основном на грязных IP, grpc
работает; обычный socks5 через ssh тоже работает. Обсуждали связку VLESS + REALITY + RAW + XTLS Vision против httpx.

Пошёл прогресс по теме паттернов трафика: в обсуждение кинули большой тред на GitHub, нашлась ссылка на PR Xray-core #5414.

🛠 olcrtc, WBStream, Telemost, Jitsi и VK calls

Из ветки «Вопросы»: участник подтвердил, что WB и Телемост без БС работают, а сам Телемост пробил БС в Тверской области, где «все CDN отвалились» — по

По Телемосту 3.0: служебные API найдены (50+), в т.ч. 10 валидных CSRF, токены для входа от имени пользователя. Прямые запросы на API отвечали 403/404,

Из «Вопросов» про Jitsi: сервера пингуются, но подключение не проходит; настройка была jitsi + datachannel по умолчанию. Звучала версия, что изменилось
тело запроса или добавились новые типы передачи — пинг проходит, а пакеты могут просто откидываться.
